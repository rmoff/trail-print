# Trail Print

Turn a run, ride or hike into a 3D-printable terrain tile: the land around your route in
relief, your route raised on top, start and finish marked, and a title, place and stats
set into the underside.

**Use it: https://trail-print.rmoff.net**

Drop in a GPX file (from Strava: open the activity, use the ⋯ menu, then Export GPX), pick a
shape, size and colours, and download a file for your slicer.

No GPX to hand? *Try an example* on the start page (or open
https://trail-print.rmoff.net/?demo) loads the course of the Wharfedale Three Peaks fell race
from Kettlewell in the Yorkshire Dales (`public/demo/`, a recorded run with times and heart
rate removed and the track thinned to about 2,200 points).

## What you get

- **3MF for Bambu Studio and OrcaSlicer.** One object, with each colour a separate part
  already assigned to its filament slot:
  four colours = land, water, route, start/finish markers and text;
  two colours = land and water, route and text;
  one colour = everything in one, with the text engraved into the underside.
- **3MF for PrusaSlicer or Cura.** The same parts in PrusaSlicer's own layout.
- **STL.** Everything merged, for one colour.

Options: hexagon, circle or square; size (with *Fit to plate*); 0.4 mm or 0.2 mm nozzle;
hill exaggeration; how much land to show around the route; the three lines of text. The
preview shows the tile on your printer's build plate (ten common printers, or enter your
plate size), with a see-through purge tower where colour changes need one.

## Privacy

Everything happens in your browser. Your GPX file is never uploaded: the site is static
files only, with no server code. The page downloads terrain and water map tiles for the area
around your route, and asks OpenStreetMap's Nominatim for the name of the place near your
start (sent rounded to about a kilometre). Your last run and settings are kept in your own
browser (IndexedDB) so a reload picks up where you left off; *Start again* clears them.

## How it works

1. **Route:** GPX track points are projected onto a flat local map (metres).
2. **Shape:** the tile outline is fitted around the route with the chosen margin.
3. **Terrain:** heights come from [Terrain Tiles on AWS](https://registry.opendata.aws/terrain-tiles/)
   (Terrarium PNGs), at a zoom matched to the mesh spacing. The top surface is a regular
   triangular lattice that exactly covers the hexagon, circle or square.
4. **Water:** the `water` layer of [OpenFreeMap](https://openfreemap.org) vector tiles
   (OpenMapTiles schema: sea, lakes, wide rivers), rasterised and flattened to a level per lake.
   Water is a separate thin part sitting in a matching dip in the land.
5. **Route and markers:** a raised strip that follows the finished surface, built from
   overlapping closed pieces with round joints.
6. **Text:** laid out with [opentype.js](https://opentype.js.org/) in the Fredoka font, cleaned
   with [polygon-clipping](https://github.com/mfogel/polygon-clipping), triangulated with
   [earcut](https://github.com/mapbox/earcut) (each triangulation is checked for exact cover
   and matching edges), and set flush into the underside, mirrored so it reads when the tile
   is turned over.
7. **Export:** every part is a closed, outward-facing mesh. The Bambu 3MF uses Bambu Studio's
   project layout (it only honours per-part filaments in files it recognises as its own);
   the file has no print settings, so Bambu Studio says it is loading geometry only and keeps
   your own printer and filaments.

Nozzle settings (`NOZZLES` in `public/js/model.js`):

| | 0.4 mm | 0.2 mm |
|---|---|---|
| terrain mesh spacing | 0.5 mm | 0.3 mm |
| route width / height above ground | 1.2 / 1.2 mm | 0.7 / 0.8 mm |
| start/finish marker diameter | 3.2 mm | 2.0 mm |
| text depth | 0.6 mm | 0.4 mm |
| smallest font size | 5.5 mm | 3.5 mm |

## Code

```
public/            the site (static files)
  index.html, style.css
  js/app.js        page logic: loading files, settings, map data, downloads
  js/worker.js     builds the model in a Web Worker
  js/model.js      geometry: terrain lattice, water, route, markers, text pockets
  js/text.js       font outlines -> clean polygons
  js/underside.js  fits the three lines of text inside the tile; messages about them
  js/export.js     3MF (Bambu and PrusaSlicer layouts) and STL writers
  js/plate.js      printer plates: fit and purge-tower room
  js/gpx.js, geo.js, dem.js, water.js, mesh.js, preview.js (three.js), saved.js
  vendor/          generated by build.sh (libraries and fonts from node_modules)
test/              unit tests (node --test) and Playwright end-to-end scripts
tools/             check files in Bambu Studio's command-line slicer
```

```
npm install
./build.sh                 # copies libraries + fonts into public/vendor, writes public/_headers
npm test                   # geometry, text fuzzing, 3MF contents, GPX parsing, plates
npx wrangler dev           # local copy at http://localhost:8787 with the production headers
node test/e2e.mjs http://localhost:8787/ path/to/run.gpx out/e2e
node test/e2e-reload.mjs http://localhost:8787/ path/to/run.gpx
node test/e2e-phone.mjs http://localhost:8787/ path/to/run.gpx    # touch: spin, scroll, tap, download
node test/e2e-sizes.mjs http://localhost:8787/ path/to/run.gpx    # phone/tablet/desktop sizes fit the screen
```

Put your own GPX files in `test/fixtures/` (git-ignored). `wrangler dev` does not notice
files newly added under `public/`; restart it after adding one.

`tools/bambu-slice.sh` slices a 3MF with Bambu Studio's command line (Flatpak) for an
A1 mini to check colour changes and purge-tower placement. It needs fully resolved
profiles, made by `tools/resolve_profile.py` from the profiles shipped with Bambu Studio.

Deploying is a static-assets Cloudflare Worker (`wrangler.jsonc`):
`CLOUDFLARE_API_TOKEN=… npx wrangler deploy` (runs `build.sh` first).
